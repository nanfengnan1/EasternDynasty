# 历史形貌与人物辨识度

用于历史人物立绘、卡牌及多人系列。统一绘画质感和版式，分别建立人物身份。用户提供的明确设定优先；与史料不同的创作设定保留说明。

## 从资料到造型

检索人物本传、纪传及可核查的原始文献，寻找形貌而非只看功绩。优先记录原文位置、出处链接、简短摘录和适用年龄；人物同名时先核对时代与身份。无法联网或资料不充分时明确记录限制，仍可完成带假设的美术设计。

将依据分开保存：

- `direct_description`：文献明确写到的身材、脸型、须发、姿容等。史籍记载也有作者立场，不等于可验证的本人照片。
- `contextual_inference`：根据生卒、事件阶段、身份和生活环境作出的推定，例如描绘时的大致年龄。不能据此推出具体鼻形或眼距。
- `later_depiction`：后世画像、雕塑和影视造型。注明年代和性质，不冒充同时代肖像。
- `artistic_design`：为缺少记载的五官、发型、肤色和姿态所作的原创补足。

“雄姿”“英伟”“仪表不凡”等词不能推出唯一五官。古代身高不机械转换为精确厘米。出生异象、神光、龙颜等修辞或神异叙事，不直接画成生物特征。民族、阵营和善恶评价也不能自动决定鼻形、肤色或美丑。

## 独立人物档案

每张建立简洁的 `portrait_profile`，按需要填写描绘年龄、体态、脸部轮廓与长宽比例、颧骨与下颌、眉眼形态与间距、鼻梁与鼻翼、嘴唇与人中、发际线和须发。指出哪些来自证据，哪些是创作；无须机械填满所有字段。

多人设计先建立差异矩阵，避免全部落成“中年、剑眉、鹰目、高鼻、山羊须、金甲”。至少让影响辨识的脸部轮廓、五官比例和年龄/体态呈现有意义的组合差异；不为追求差异而添加无依据的伤疤、残疾或夸张族群特征。相同年龄、同属文臣或武将也应有各自的脸。

将资料存入同名 `.design.json`，推荐字段：

```json
{
  "character": "人物姓名",
  "depicted_stage": "选定的生涯阶段及大致年龄",
  "appearance_evidence": [
    {
      "kind": "direct_description",
      "source_title": "史籍与卷次",
      "url": "实际查阅的来源链接",
      "passage": "简短形貌原文",
      "interpretation": "可以支持的视觉特征",
      "limits": "不能由此推断的细节"
    }
  ],
  "portrait_profile": {
    "face_shape": "明确轮廓",
    "brows_eyes": "眉眼结构",
    "nose_mouth": "鼻与口部比例",
    "hair_beard": "发际线与须发",
    "build_age": "体态与年龄感"
  },
  "artistic_assumptions": ["没有文献支持的补足"],
  "avoid_resemblance_to": ["同批次不应混同的人物"],
  "review": []
}
```

这是设计记录，不是新增必填输入；现有请求中仍用 `character.appearance` 汇总用于生图的外观。结果 `artifacts` 可用 `kind=manifest` 引用设计记录。

## 隔离参考图的身份影响

跨人物共享完整卡片，容易连带复制五官、姿态和构图。换名、换甲、换背景以及一句“不同人物”通常不足以解决。

- 默认用不含人脸、头部、人体轮廓的空白框架参考，或纯文字布局规格。
- 已有参考含其他人物时，可通过宿主实际图像编辑能力生成空白框架，检查人物是否完全移除，再作为布局参考。遵守宿主图像工具的规定，不以未经允许的代码改图代替。
- 构图复杂或持续同脸时，先生成独立人物立绘，通过辨识度检查后再加卡框。只对同一个人物使用其身份参考。
- 不把刚生成的甲人物卡继续作为乙人物的身份或整体样式图。

## 生成与检查

在展开大批次前，先完成少量差异明显的代表人物，实际对比后再延续。选择不同脸型、年龄和体态有助于检验流程，但不要把人物史实改造成固定模板。

逐张查看姓名、文字、星数、人体结构之外，还要检查：

1. `史料形貌落实`：明确可用的记载是否体现在图中；推断和美术补足是否单独记录。
2. `人物辨识度`：忽略姓名、阵营、甲胄和背景，只看脸部及体态，能否区分相邻人物。
3. `参考身份污染`：是否继承了另一人物相同的眼鼻口比例、脸部轮廓或表情姿态。

可并排查看原图或制作仅用于检查的预览，不能仅凭提示词不同、图像文件哈希不同就判定身份不同。不要求机器相似度分数；如使用分数，只作辅助，不能冒充历史身份验证。

明显同脸时暂停批量扩展，先排查共享参考。修正身份结构并重新生成；必要时去掉人物参考，仅保留无脸框架。每张修正上限遵循请求和主技能。未通过的候选使用 `review_required`，标出失败项并保留旧稿，不以已生成文件数量代替合格交付数量。
