# 武将图片设计技能：使用说明

## 最简单的用法

在能访问本机文件的 AI 对话里发送：

```text
请读取 F:\工作项目\率土之滨\skills\design_character_skills\SKILL.md，
按照里面的流程，设计一张岳飞的五星武将卡。
参考率土之滨风格，银甲红披风，竖版 2:3。
先查看技能包中的参考图片，再使用实际可用的图像工具生成并检查。
其他没有指定的外观细节由你合理设计。
```

这段文字是一条交给 AI 的任务，不是在 PowerShell 中运行的命令。换电脑或移动目录后，应把入口路径替换为实际路径。

如果 AI 无法访问本机文件，给它上传整个技能包，或者同时提供 SKILL.md、相关参考文件和图片；只发送本机路径不能让远程 AI 自动读到文件。

## 名称分别是什么意思

| 名称 | 用途 |
| --- | --- |
| design_character_skills | 这个文件夹的名字 |
| design-general-card | SKILL.md 中定义的技能名称 |
| design_general_card | JSON 工具契约中的函数名称 |

当宿主已经发现并加载此技能时，可以使用：

```text
$design-general-card 为岳飞设计一张率土风格的五星武将卡。
```

是否支持这个快捷写法，取决于使用的 AI 客户端。仅把文件放进任意文件夹不代表所有客户端都会自动发现它。要明确使用本目录这份说明，优先采用上面的“读取 SKILL.md 路径”方式。

## 需要提供哪些内容

最低限度说明要画谁；能从当前上下文确定人物时无需重复填写。

| 信息 | 是否需要提供 | 未指定时如何处理 |
| --- | --- | --- |
| 武将姓名或明确人物身份 | 需要 | 无法确定时先询问 |
| 完整卡片还是纯立绘 | 可选 | 默认完整卡片 |
| 画风或参考游戏 | 可选 | 默认 historical-strategy 历史策略画风 |
| 参考图片 | 可选；修改已有图时需要目标图片 | 可用文字方案，不能假称已使用缺失图片 |
| 星级 | 卡片可选 | 默认五星 |
| 画幅 | 可选 | 默认竖版 2:3 |
| 服装、兵器、姿态、表情 | 可选 | 按人物与风格合理设计，并说明重要假设 |
| 阵营 | 可选；自定义游戏阵营建议提供 | 用户指定优先；允许后按历史推定，有歧义时询问 |
| 初始技能、技能描述 | 可选 | 给定、沿用已有设定，或明确允许原创 |
| 历史简介 | 可选 | 可以要求 AI 查证后撰写；未要求时不主动添加 |
| 属性、COST | 可选 | 不自动编造；需要原创时请明确允许 |
| 图片输出 | 可选 | 默认 1 张，不透明背景，偏好 PNG |
| 修改要求 | 修改已有图时需要 | 说清要改什么、保留什么 |

“历史策略画风”与“率土参考风格”是两个预设。希望沿用慕容垂示例的视觉体系时，请写“率土风格”或指定 `stzb-inspired`。

## 阵营、初始技能与历史描述怎么填

这四项都可以提供，但不必每次全部手写：

- **阵营**：给定你的游戏阵营，例如“燕”。也可以明确说“阵营按历史确定”；角色跨阵营时 AI 会询问或说明所采用的时期。
- **初始技能**：给技能名称；需要 AI 设计时写“允许原创技能”。已经确定的技能可以直接要求沿用。
- **技能描述**：给需要展示的效果与数值。未定义机制时，不把一句意境文案冒充具体技能效果。
- **历史描述**：可以直接写“历史简介由 AI 核实后撰写”，无需提供全文；它与技能描述分别排版。

例如：

```text
使用 design_character_skills，设计慕容垂的五星武将卡。
风格参考率土之滨，银甲红披风。
阵营：燕。
初始技能：龙城再起。
技能描述：沿用示例的概念文案“整军蓄势，铁骑破阵。”
历史简介：由你查证后写一段简短介绍，显示在卡面。
属性沿用已有示例，不编造新的技能数值。
```

结构化输入对应：

```json
{
  "schema_version": "1.1",
  "character": {
    "name": "慕容垂",
    "faction": "燕",
    "biography": {"mode": "auto"}
  },
  "card": {
    "stars": 5,
    "ability": {
      "label": "初始技能",
      "name": "龙城再起",
      "description": "整军蓄势，铁骑破阵。"
    },
    "show_biography": true
  }
}
```

这份技能新增字段使用 1.1；旧的 1.0 示例仍然可读。若不要历史简介，可省略 biography，或将其 mode 设为 omit。可查看 [银甲红披风实际成品](examples/murong-chui-silver-v2.png) 和 [生成检查记录](examples/murong-chui-silver-v2.result.json)。


## 历史形貌与避免同脸

历史人物会优先查找史籍中的容貌、体态和年龄线索，保存出处；没有明确记载的五官会作为美术设定说明。人物外貌查证不会自动在卡面增加历史简介。

多人卡牌统一边框和画风，但分别设计脸型、五官比例、年龄感及体态。共享参考优先采用无人物的空白卡框，不反复将同一张人物卡输入给所有角色。生成后会横向对比，明显同脸的候选应返修并标记为待检查，不能以换衣服或换姓名冒充独立人物。

可直接说：“根据可核实的历史形貌描述设计这批人物；没有记载的部分合理补足并标注；每位有独立面部特征，检查整批是否同脸。”详细规则见 [历史形貌与人物辨识度](references/historical-identity.md)。

## AI 什么时候会问问题

- 只说“调用这个技能”，且上下文没有人物：先问“你想设计哪位武将？”
- 给了姓名和明确要求：直接开始，不重复确认。
- 姓名有歧义、人物身份参考缺失、要求彼此矛盾：只询问影响结果的关键信息。
- 修改已有图片却没有提供目标图：先索取目标图。
- 衣服颜色、姿势等可合理设计的细节：使用默认或合理假设，不强制填写完整问卷。

用户明确要求“先问我再设计”时，先收集要求；否则不把所有可选字段变成必须回答的问题。

## 可以直接复制的任务

### 完整卡片

```text
读取本技能的 SKILL.md。为慕容恪设计一张五星武将卡，
使用 stzb-inspired 风格，保留示例的细金框和竖排名签。
人物、服饰与姿态重新设计；不要沿用慕容垂的属性或战法。
```

### 纯立绘

```text
读取本技能的 SKILL.md。为岳飞设计一张历史策略风格的纯立绘，
竖版 2:3、透明背景，不要卡框、星级、姓名或属性文字。
```

### 修改已有卡片

```text
读取本技能的 SKILL.md，并查看我提供的原图。
只将披风改成深蓝色，保持人物面容、姓名、星级、属性、边框和布局不变。
另存修改后的图片。
```

这条任务需要同时提供原图或可访问的图片路径。

### 只要提示词

```text
读取本技能的 SKILL.md。为李靖准备一份完整武将卡设计提示词，
采用历史策略画风。先不调用生图工具，返回准备好的提示词。
```

这种情况返回 `prepared`，不会声称已经生成图片。

## 给其他 AI 或程序的结构化用法

让 AI 读取 [接口约定](references/interface.md)，然后使用 [工具契约](references/tool-definition.json) 的输入 schema。最小示例：

```json
{
  "schema_version": "1.0",
  "asset_type": "card",
  "character": {
    "name": "岳飞",
    "era": "南宋"
  },
  "style": {
    "preset": "stzb-inspired"
  }
}
```

更完整的例子在 [慕容垂请求](examples/murong-chui.request.json) 和 [纯立绘请求](examples/minimal-portrait.request.json)。引用图片的相对路径以请求 JSON 所在目录为基准；单独移动 JSON 时要一起移动图片或修正路径。

把 JSON 贴给普通聊天 AI 时，可以补一句：

> 按本技能处理这份请求，先检查图片和生成工具，完成后返回成品与检查结果。

`design_general_card` 是接口契约里的名字，本包没有部署 HTTP/MCP 服务。程序接入仍需要实现实际工具处理器；单独提供 JSON 不会自动产生图像调用。

## 正常会得到什么

- 可查看的武将图片或卡片。
- 最终使用的提示词。
- 真实的文件路径或宿主提供的资源链接。
- 姓名、文字、星级、构图等检查结果，以及尚未满足的要求。

图像工具不可用时，AI 应明确说明并可交付提示词；不能只返回一个不存在的图片地址。默认每张图最多自动修正两轮。位图卡片是设计成品，不自动包含可编辑 Figma 图层或可运行游戏 UI。

本包已有 [慕容垂实际成品](examples/murong-chui-card-v1.png) 和 [结构化结果](examples/murong-chui.result.json) 可供参考。
