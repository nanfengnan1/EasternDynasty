# Eastern Dynasty：率土视觉研究与第一轮样板规范

研究日期：2026-10-24。状态：本轮资料研究完成；未修改游戏代码或制作正式美术。后续继续研究由任务再次触发，本轮没有创建周期调度。

## 结论与证据边界

当前最值得改善的是三件事：让地图成为主画面，让武将具有可识别的人物形象，让资源、城市、归属与行军形成清楚的信息层次。增加描边或改几种颜色只能解决其中一小部分。

本报告实际查看了原型的地图、武将和招募截图，以及 13 张官方公开图片；其中部分是旧版本界面或营销合成图。它们能支持构图、层级和地图表现的研究，不能证明当前大陆客户端的全部样式、规则或底层实现。官方样本、发布日期和本地文件一一对应见 [来源与观察记录](Source-Catalog.md)。

标记约定：**观察**是图中直接可见或官方文字明确陈述；**推断**是据此作出的设计解释；**提案**是 Eastern Dynasty 自己的目标，尺寸、配色和资产预算均属于提案。

项目规则以 [Rules.md](../Rules.md) 为准：固定历史背景、三个出生文化区、跨区攻占默认城池解锁全池；魏蜀吴是卡池分类，不意味着黄巾开局已有三个国家。原型的 19 个条目也不等于最终约 160 人史实名单。

## 2. 武将与卡牌：值得学习的结构

**观察：**[官方图鉴](https://stzb.gamedreamer.com.tw/plate.html)提供星级、阵营和 COST 等筛选；[2022 招募公告](https://www.daisangoku.com/news/official/20221024/31170_1048138.html)的武将预览图以竖卡平铺，每张卡主要面积由人物占据，星级置顶、阵营/姓名贴边、等级等信息压在底部。招募主界面则用较大人物图识别卡池，把消费按钮放进当前卡池区域。这里研究信息组织，不沿用公告中的价格、倒计时或保底规则。

三张实际查看的图鉴立绘显示了不同的视觉办法：

- 皇甫嵩：正面稳定构图，面部白发与胡须、胸部手势、纵向剑身构成识别中心；两侧士兵弱化为背景。脸与手的亮度高于大面积盔甲。
- 轲比能：三分之二转身、手按刀柄，毛领、皮革与金属局部构成不同材质，披带和天空提供方向感。
- 荀彧：本次图鉴样本是线条较强的旧绘风格，有蓝袍、马匹、佩剑与月色背景；与前两张写实度不同。不能把这些年代混杂的样本称为统一的现行美术规范。

**推断：**人物识别依赖姿态、脸部、轮廓和道具的组合。把全身都做成同样高对比的细节会削弱头像缩小时的识别。游戏立绘的夸张服饰只能作为游戏美术观察，不构成汉代服饰考证。

### 本项目的原创卡牌规范

| 项目 | 第一轮执行值与规则 |
| --- | --- |
| 比例与尺寸 | 竖卡宽高 2:3；1440×900 基准页面使用约 168×252 的目录卡，详情可放大到 336×504；窄窗口减少列数。 |
| 构图 | 人物是主视觉，约占画面 65%—75%；面部放在上部三分之一附近，确保头肩缩略图仍可辨认。为边缘标签留安全区，不用文字压脸。 |
| 画风 | 选择统一的半写实绘画：真实体块、可辨材料、适量笔触，减少全身高亮金边。背景低对比、低细节，为人物服务。 |
| 标签 | 左上为“汉地/草原/东北”的文化徽章；魏蜀吴等卡池标签与文化区分层，避免两个不同概念共用一个图标。 |
| 星、阶、等级 | 1—5 星只表示星级；底栏显示 `Lv.18 / 40`；独立印章显示 `2 / 4 阶`。进阶改变印章和数字，不增加星数，不把星色同时用作等级。 |
| 姓名与副本 | 姓名 20—22 px；必要时加版本/兵种标签。同名副本需显示是否上阵、等级和阶数。 |
| 技能 | 目录卡最多展示自带技能缩略符号；详情清楚区分“自带”“可学”“拆解所得”。保留原型已实现技能数量，不为美术模板增加未确认规则。 |
| 选中态 | 外边框加轻微亮度与角标，整卡不发大面积白光；上阵标记与选择标记分开。 |

武将页建议分为左侧 220 px 筛选、中央弹性卡格、右侧 320 px 详情。编队页单独突出“前锋／中军／大营”三个位置与同一套头像，不把全部培养操作堆到地图侧栏。拖拽与点选可分别评估，第一轮先保证点选换将流程清楚。COST、兵种克制等本项目未定规则只记录扩展位置，不据参考图擅自实现。

招募页第一轮保留现有两种招募入口。每个池有一幅原创人物主视觉、醒目的成本和星级范围；“当前开放汉地”“跨文化区攻占默认城池后全量开放”作为统一状态条。灰态必须同时说明缺少的条件。概率入口固定可见；抽取结果沿用目录卡结构，展示新增/同名副本和进阶用途。抽卡动画要可跳过，跳过不跳过结果确认。该页不引入参考游戏的活动日历或赛季推进。

## 3. 原创 UI 基线

方向为“军府案牍与山河沙盘”：暖纸色用于阅读、深墨色用于地图 HUD、旧铜色用于重点、朱砂用于确认动作。装饰控制在边角、分隔和印章，不给每一个数值套厚重花框。

| 角色 | 建议色值 | 用法 |
| --- | --- | --- |
| 纸底 | `#E9DFC8` | 武将详情与说明页，避免大面积纯白 |
| 墨底 | `#1D2929` | 地图 HUD 与面板 |
| 主字／辅字 | `#F0E9D9` / `#B8C0BA` | 深底正文／次要说明；浅底使用 `#2B302D` |
| 旧铜 | `#BEA16B` | 标题、选择边框、小部分稀有度装饰 |
| 朱砂 | `#A54C3B` | 当前主要动作；同屏少量使用 |
| 我方／敌方 | `#4F8B83` / `#BB6658` | 配合旗形、文字和边线样式，不只靠颜色 |
| 警示 | `#D2AE65` | 库存不足、拥堵等可行动提示 |

以上颜色是本项目提案；正式落地后需在实际显示器和截图上验证文字对比。禁用按钮保留可读文字与原因，不能仅把整块透明度降到几乎看不见。

标题建议思源宋体 SemiBold，功能文字和数字建议思源黑体 Regular/Medium。字体导入时保存上游许可，依据：[思源黑体](https://github.com/adobe-fonts/source-han-sans/blob/master/LICENSE.txt)、[思源宋体](https://github.com/adobe-fonts/source-han-serif/blob/master/LICENSE.txt)。先选明确的字体文件与子集策略，再确认是否替换当前系统字体。

以 1440×900 为设计基准：页面标题 28—32 px，区块标题 22—24 px，正文/按钮 16—18 px，次要标签 14 px，资源主值 20—22 px。主要操作目标高度至少 40 px；常规间距使用 8/16/24 px。标题层级靠字号、位置和留白建立，不把所有文字都染金。适配需覆盖 1280×720、1440×900、1920×1080；密集小字优先减少展示内容。

### 地图 HUD 的第一轮布局

- 顶部资源栏高 64 px：左端势力与坐标，中部五类常规资源，右端灵玉及简短入口。资源值大于增速字，过长数值用统一单位并保留详情。
- 左侧约 72 px 导航：领地、武将、招募、战报，图标带短标签；选中态只强调当前项。
- 底部高 64 px：最多三支当前关注部队的缩略状态和地图主要操作。保存、倍速等低频功能可收入菜单。
- 右侧 300 px 对象详情仅在选中地块、城池或部队后展开；关闭后释放地图。默认宽幅画面地图可见面积目标至少 75%，有详情时允许下降。
- 地图上只留城名、选中对象、必要行军计时。屏幕空间接近的标签合并或按重要性隐藏。

这是对当前截图的布局修正目标，并不是对率土客户端布局尺寸的测量。2021 年[项目组界面优化公告](https://www.taptap.cn/moment/192011711086068472)也把按钮状态、字和图标可读性、点击区域以及资源地识别列为改进项，可将这些直接转成我们的截图验收标准。

## 4. 地图：从逻辑地格到连续山河

**观察：**[2023 官方地图升级](https://stzb.gamedreamer.com.tw/NewsContent/zh_TW/stzb2_news_7416.html)的山脉图有连续脊线、沟壑和坡脚过渡；河流图有弯曲河道、浅水边、岩岸和沿岸植被；远景仍保留河谷、山系和聚落的位置关系。资源农田位于连续土地之上。截图不能揭示其网格、纹理算法或 LOD 实现。

**观察：**[日本官网宣传图](https://www.daisangoku.com/)中的城市包含城墙、门楼和密集房簇，主城规模明显高于周边地物。另一张战争合成图显示细行军线、方向箭头、地面圈和军旗；这是广告画面，不能据此认定当前游戏在所有模式下都采用相同表现。

### 按镜头层次组织信息

| 镜头 | 应看到的内容 | 应减弱的内容 |
| --- | --- | --- |
| 战略远景 | 九州/文化区标签，山脉与水系，主要默认城池，势力边界，关键行军方向 | 单棵树、每块资源的数字、房屋细节 |
| 常用中景 | 城门/城墙轮廓、营帐簇、粮田纹理、矿石簇、树林、道路和河岸；选中资源等级 | 全部格线、重复文字标签、每栋房屋的小装饰 |
| 战术近景 | 房屋层次、树冠差异、河滩、简洁人马/军旗，选中地块收益和守军 | 与操作无关的微观细节；近景不是城市建设模拟器 |

**提案：**逻辑格保留，用连续网格或地形承载视觉。普通格边在常态下隐去或极淡；悬停显示一格轮廓，选中显示更明显轮廓；我方领土以外边界和低强度覆盖表示，敌方再加不同边线样式。归属不应把原本的粮田或河岸完全染成纯色。

资源需要形状识别：草料用草垛/草场，粮食用田垄和谷仓，石料用浅灰采石断面，铁器资源点用矿口、矿料和小型冶炼设施表现生产链，金币以集市/聚落或既定收益来源表示。具体资源点如何产“铁器”仍由规则定义，图标不要直接画成金属锭就掩盖规则含义。等级用旁侧数字徽标，资源高等级增加作业规模与构筑物，不仅改颜色。

默认城池与玩家城池使用两种可辨的基础轮廓或旗帜。等级靠城墙周长、门楼和中心建筑变化显示；选中后再出现准确等级与奖励。草原营地采用帐群、牲畜围栏和集会空间，东北汉人据点与林地聚落分别建型，不把东北所有城市统一画成毡帐。

行军用一条有方向的细路径、代表部队的旗/小模型、近终点的计时；选中时增强路径亮度。战斗地点用克制的短闪/交锋图标，战报是详细结果的主入口。草原可见地形不同，不等于美术层直接改移动规则。

## 5. 三个区域的视觉区分

以下都是待考证的艺术方向。真实地理有过渡，文化内部也有不同身份；不能以一个地区的全部人物都穿同一种服装代替设计。

| 区域 | 地表与建筑方向 | 人物方向 | 需补充的考证 |
| --- | --- | --- | --- |
| 汉地 | 河谷农田、土色道路、夯土城墙、灰瓦与木构，九州用植被/水系/地形区别 | 军士、文职、地方豪强的剪影不同；布、皮、甲与冠帻分工明确 | 汉末甲片、冠帻、印绶、建筑屋顶与县城形制 |
| 草原 | 开阔地、起伏缓坡、较稀疏林带、成组可迁营帐与围栏 | 骑乘姿态、便于动作的服装与弓具；毛皮只是部分材质 | 鲜卑/乌桓等各自器物证据；避免套用后世蒙古帝国装束 |
| 东北 | 辽河一带农耕城镇与林地、河网聚落并存；冷暖色随环境，不统一常年积雪 | 辽东汉人、边地骑士、不同林地/渔猎群体各设子类 | 各群体在汉末的具体分布、房屋材料、渔猎工具；避免把地理区当单一民族 |

每一套人物先完成三视图/剪影和材料小样，再做最终立绘。文化识别主要来自服饰结构、道具和姿态，不能依赖夸张面部族群特征。

## 7. 第一轮可评审样板与执行顺序

先完成一个可反复截图对照的小样：**一段汉地河谷地图 + 紧凑 HUD + 皇甫嵩原创卡面与详情 + 两类招募池的视觉模板**。地图选 24×24 逻辑格的局部内容：一座县城、一处玩家据点、一段河弯、三组连接山脊、两类树林、四类资源地、一次可见行军。它是验证范围，不修改大地图规则或格子尺寸。

第一轮必须可评审的状态：地图无选择、选择粮田、选择默认城池、行军途中、武将目录、武将详情、招募前与结果。保留同一机位、分辨率与存档内容用于改前改后对比。

详细资产与验收见 [执行清单](First-Pass-Backlog.md)。先确认人物画风与地图中景，再扩草原/东北完整模型库和 160 人名单。
