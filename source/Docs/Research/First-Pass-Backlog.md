## C. 地图技术交接建议

这里列艺术侧的实现要求，具体 Unity 官方依据、导入步骤和性能分析交给 [Unity实施建议](../../ResearchLibrary/UI-Modeling/Unity-Implementation.md)与 [地图建模资料](../../ResearchLibrary/UI-Modeling/Map-Modeling-Notes.md)。不是对率土引擎的逆向结论。

1. 逻辑网格与视觉地形分离，选取、占领、行军依旧使用原有ID。可从16×16或32×32逻辑格的渲染分块开始试验，比较每块对象数量、地表接缝、修改覆盖层成本后再决定，数值不是实测最佳值。
2. 连续底色跨越格子边界；草地/裸土/耕作覆盖层按环境混合；地块归属另作覆盖层。连续河网与山脉不要以单格独立随机高度拼成断裂台阶。
3. 模型准备近/中/远三级：近景城门屋顶，中景合并房簇，远景清楚轮廓与城标；树与岩也要有简化版本。按画面占用大小评审切换，具体LOD阈值用真实镜头测试。
4. 相同树石使用共享网格和材质；是否采用GPU实例化、网格合并与阴影方式，以当前渲染管线和性能测试为准。先做地图样板再确定管线迁移。
5. 预设固定太阳方向、环境光和色调；细节材质在真实光照下检查。先验证轮廓、接触关系和阴影，再加高成本水面或天气效果。

## D. 样板评审方法

交付8个固定状态截图：无选择地图、粮田选中、默认城池选中、行军途中、武将目录、武将详情、招募前、抽取结果。保存相同分辨率、相机位置和临时测试存档条件。

每项使用0—2分：0=不可辨/不成立；1=能用但仍明显占位；2=清楚且风格统一。

| 指标 | 2分的可观察条件 |
| --- | --- |
| 地图主次 | 无选择时大地图显著占主画面；UI主动作与资源可在短时间找到。 |
| 地形连续性 | 河岸、山脊、树林在中景连续，资源格仍可选中。 |
| 城市层级 | 默认县城、玩家主城、营地、资源设施剪影可区分。 |
| 角色识别 | 缩小后能靠形象区别三名角色；星/阶/等级不混淆。 |
| 操作状态 | 默认、悬停、选中、禁用、上阵、锁定具有清楚区别。 |
| 风格一致 | 字体、配色、线宽、插画明暗与地图气氛协调。 |

评分是团队比较工具，不是正式测试结果。样板合格还需验证游戏选择、招募、配将、保存和行军功能没有回归，并记录实际客户端的帧时间/对象数量；本报告没有运行性能测试。

下一轮只处理对照中仍有明显差距的项目。角色大批量制作、动态立绘、全域高细节建模、完整商人界面在样板方向确认后逐步展开。
