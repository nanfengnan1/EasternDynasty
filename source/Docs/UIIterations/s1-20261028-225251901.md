# 地图右下招募菱章与完整人物

本轮完成地图招募区域的分层设计、Inkscape 实际导出、两张正式组件和 Runtime 接入。**源码完成，运行观感仍待发布者验收**；下述设计预览不是新游戏截图，也不表示 Windows/APK 已更新。

## 原图、基线与三个差距

实际打开了 `STZB-0527`（2023-02-01，720×405，历史玩家地图）与 `STZB-0499`（2021-12-22，2340×1080，六周年界面展示）。0527 年代较新，但右下招募区域不完整，不能猜补；0499 明确显示独立右下菱章和分离标题，因此采用其**构图**。两图当前 S1 适用性均为 unknown。原图路径、原始尺寸及 SHA 见[设计规范](../DesignUI/s1-20261028-225251901/design-spec.json)和[展示资料核验](../../Validation/UIRound/s1-20261028-225251901/presentation-source-audit.json)。

游戏基线为 204 版发布私有副本 `Project/Validation/Visual/` 内桌面 `s1-20261028-204251299-youzhou-1440x900/smoke-hud-header-ledger.png` 与手机 `s1-20261028-204251299-mobile-1600x720/smoke-hud-header-ledger.png`，均实际查看。214 轮修改卡面，不能把 204 地图基线称为本轮运行结果。只读查看了同版主城底栏图，用于识别共享底栏的遮挡风险。

三个具体差距与处理：

1. 原图招募是可辨认的独立视觉重心，基线却把人物限制在 40×38 框内；240×348 原图等比适配后实际仅约 26×38。本轮使用 60×88 框，完整图实际约 60×87，人物可见面积约为原来的 5.2 倍，不裁头或放大低清截图。
2. 基线招募与其他底栏项目几乎同高，缺少原图的独立右下构图。本轮采用 160×140 菱章区域，超出原 78 高底栏向上 66 单位；其余五导航和保存/时间位置不变。增加的占位如实记录，不称节省地图面积。
3. 基线人物、短菱章与标题挤成一层。本轮图片、菱章、底座与 140×24 动态标题分离，人物底部与标题留 16 单位间隔；正常/悬停有独立导出状态。标题保持真实中文控件。

原作是书法招募符号，本轮沿用项目已有 `portrait.s1_100039` 人物插图和菱章语言进行适配，**未恢复原作书法图标**。人物仍带现有矩形源图背景，不是新抠图或保证抽中该武将。未改变卡池、价格、规则、存档或招募结果。

## 实现与输入保护

`MapHudNavigationLayout.cs` 新增地图招募专用 Entry/Art/Caption 几何，`MapHudPresentation.cs` 读取 `ui.youzhou.map_recruit_seal` / `ui.youzhou.map_recruit_seal_hover`（均 320×280）。通过 `Tools/Import-Asset.ps1` 受控导入，旧 `nav_recruit` 与已有 meta 保留；新 meta 由发布正常导入生成。

只有地图未选地时显示大菱章。代码检查发现土地命令面板最下方可到 `height-100`，会与新招募的 `height-144` 起点重叠 44 单位，因此选地时保留原紧凑招募，退选再展开。主城保留旧入口，避免对未重新设计的子页引入遮挡。新完整矩形加入 `Block`，城市/资源/行军标签沿既有阻挡规则避让；复用 `ContentTileClicked` 的拖动取消，不登记隐藏热区。

地图诊断检查真实贴图尺寸、字体、几何和九点地图阻挡。发布入口新增必需 `smoke-hud-recruit-seal.png` 与 `MAP_RECRUIT_SEAL_RUNTIME_OK`，保留图像和标题分别进入招募/返回；增加可见上凸人物位置的实际点击、拖动取消，以及选地紧凑/退选恢复检查。模态不暴露招募诊断和可点目标。

本轮纯布局、外部负例、统一逻辑/引用编译及正式资产来源链结果见[最终结果](../../Validation/UIRound/s1-20261028-225251901/result.json)。这些检查不证明新运行截图或真实输入已通过。
