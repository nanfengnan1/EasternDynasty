## 41 张试玩池的筛选依据

每个身份必须同时满足：官方属性可以按原始卡片 ID 唯一关联；成员关系状态为“官方曾确认”；关系指向实际招募类别；该卡没有全池移除记录，且同一卡池没有明确移除记录。

采用的类别为天下 EX、阵营轮换、赛季初限时、明确招募活动。“名将来投”仅有任务取得说明，暂时排除。以下单独出现均不足以成为可重复随机招募依据：

- “历史 S1 待归属”里的全赛季新增公告，未核实具体 S1 招募池。
- “名将云集奖励”的累计招募赠将与“不忘初心奖励”的三选一取得。
- 已结束“限时活动红颜”、历史铜钱包、历史 SP、仅历史实机确认的成员。
- 仅由 EX 合并机制推导的关系，以及明确移出该池或全池移除的记录。

同一卡片仍可由另一条有效招募关系进入试玩池。例如大乔有过已结束的红颜活动关系，也有独立 EX 招募记录；汉三英既有选一奖励，也有独立招募记录。不能因为一条奖励/历史记录而删除所有独立证据。

逐卡保留的原始关系、有效招募关系、逐关系纳入/排除理由、原版开放条件和全池移除状态见 [S1-Rag-Snapshot.json](S1-Rag-Snapshot.json)。原始 366 条关系并不等于 366 张卡；原始 22 个分类也不等于 22 个同时开放的现行招募池。

这 41 张是有证据支持的本地试玩候选集合。未复刻真实开服时刻、天下大势解锁、阵营轮换、限时持续天数与全部历次变更。不能宣称它们在当前正式服务器随时都可招募。

## 试玩招募与战法边界

- 金币池：从当前阵营的四星试玩候选中等概率选择，每次 200 金币。
- 灵玉池：从当前阵营的四至五星试玩候选中等概率选择，每次 100 灵玉。
- 晋阵营没有已满足此筛选条件的四星候选，普通池为空时不扣款；缺款或错误阵营也不扣款。
- 这些价格和概率是项目明确标识的试玩配置，不是原版商业概率。三星全量及可确认取得条件缺失，未用全赛季新增公告强行补齐。
- 属性和战法名来自本地官网字段；战法文字供查阅。战斗仍使用现有简化公式，完整战法时序、触发、冲突与拆解规则尚未实现，因此 S1 卡拆解不会消耗卡片。
- 旧版征程的原型卡、旧招募规则与存档 ID 保留，新增卡片统一使用 `s1_<原卡片ID>` 命名空间。

新建幽州试玩赠送皇甫嵩 `s1_100039`、王子服 `s1_100744`、郑泰 `s1_100746`。这是本项目的试玩起始配置，**不是官方新手赠将规则**；不替换玩家已有存档中的角色。三张的图鉴身份与图片可核验，其随机招募依据仍按上述筛选独立处理。同名 S1 的不同阵营/兵种身份可分别收藏，同一支编队只可上阵其中一张；在同一位置替换该角色的另一身份允许执行。

## 可复现导入

`Tools/Import-S1Rag.ps1` 读取固定版本的卡片数据与本地官方字段，核对同 ID 的姓名、阵营与兵种，生成 `Core/S1Roster.Generated.cs` 和证据快照。快照记录两份输入的 SHA-256。生成文件不要手改。

```powershell
& .\Tools\Import-S1Rag.ps1 -RagRoot 'F:\工作项目\率土之滨\rag' `
  -OfficialFields 'C:\Users\fenglei\Downloads\率土之滨_素材集_2026-10-25\_采集记录\cn_hero_data.json'
# 图片已完整登记，只更新数据定义与证据时：
& .\Tools\Import-S1Rag.ps1 -SkipImages
# 中断后继续图片导入：
& .\Tools\Import-S1Rag.ps1 -Resume
```

图片按 RAG SHA-256 定位并核验，JPEG 只做解码后无损 PNG 重编码，不裁切、扩图、重绘或补造细节。PNG 通过统一 `Import-Asset.ps1` 登记，保留原始官网图片 URL、输入哈希、导入用途与权属说明。官网立绘通常为 240×348，不能把它宣传成高清完整实机卡面。正式图片仍需 Unity 导入后构建。

`-Resume` 首先完整检查已登记资源。仅当条目为 ready、类型与用途一致、来源记录含对应 RAG 原图 SHA-256、正式 PNG 实际哈希仍匹配清单时才跳过图片；不匹配项目继续走原有导入/Replace 保护，不绕过坏文件、事务或 GUID 检查。特殊官网原图敬哀皇后 `100329` 为 240×340，其像素照原样保存，不强拉成 2:3。
