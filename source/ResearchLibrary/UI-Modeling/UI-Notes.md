# UI 技术与原型修正笔记

研究日期：2026-10-24。目标编辑器：Unity 6000.3.27f1。本文将官方能力说明与本项目设计建议分开；建议数值尚未通过实现验证。

## 已查看的本地画面

- [地图原型](../../Validation/Screenshots/smoke.png)：1440×900 下顶部资源容易定位，但左右固定信息栏压缩地图；大量同色长方形使主操作和辅助信息同等醒目。
- [武将原型](../../Validation/Screenshots/smoke-roster.png)：三条文字武将记录缺少人物肖像这一识别中心，页面大面积空白。当前内容少时应保留完整卡牌占位结构，让未来扩充不必重做视觉结构。
- [开局原型](../../Validation/Screenshots/smoke-welcome.png)：阵营、州、名字都有入口，但缺少选中状态的视觉层级和地域氛围。地区信息应随选择变化，而不是所有说明同时堆放。

## 优先可实施的视觉结构

下列是 Eastern Dynasty 的设计判断，不是 Unity 官方要求。

1. **地图 HUD**：顶栏只保留草料、粮食、石料、铁器、金币和灵玉；资源图标加数值，增速放悬浮说明或资源页。左侧军队栏收成可展开的小面板，右侧仅在选地后显示地块详情。底栏一级入口控制在地图、武将、部队、主城、同盟、商贸；尚未实现的入口明确显示准备中，不伪装可用。
2. **操作权重**：选地后最醒目按钮为出征或返回等当前主操作；放弃、详情是次级。资源不足、未选部队等禁用状态同时给出文字原因，不能只降低透明度。
3. **武将卡牌**：肖像占主要面积；姓名与星级固定位置；等级和进阶分开显示，例如「4星 / Lv.25 / 2阶」，避免两套成长混淆。阵营用角标或纹样辅助识别，不仅靠颜色。阵容状态用「已上阵」短标签。
4. **配队**：同屏显示三个明确槽位及候选武将卡；点击槽位后列表显示可替换对象。士兵、兵种、技能摘要靠近当前选中人物，完整技能进入详情，避免一张卡堆满全部数据。
5. **招募**：当前卡池的文化归属、可获得星级、花费及锁定原因要先于抽卡按钮出现。项目尚未确定概率和保底，原型不得展示虚构概率；当前尚未开放的跨文化卡池明确指向解锁条件。
6. **开局**：先选身份/文化，再选区域。中央主视觉可以用原创地域插画，配短说明和确认按钮。草原、汉地、东北使用共同组件与不同纹样，避免三套互不一致的操作规则。

## 字体、命中区与适配起点

建议以 1440×900 现有验证画面为第一设计基准。正文 18–20 参考像素，辅助文字不低于 16，标题 26–32；主要按钮高 44–48 参考像素、相邻按钮留 8 像素以上。它们是首轮可读性试验值，不能作为移动设备的物理触控标准。中文字体必须覆盖地名、武将名和标点，缺字回退应实测「鲜卑、乌桓、襄阳、沮授」等字符串。

至少检查 1280×720、1440×900、1920×1080、2560×1440、2560×1080：窄屏把侧栏折叠，宽屏让地图扩展；弹窗设最大宽度，避免所有内容跟随窗口无限拉长。不能只把整张 1440×900 布局整体等比缩小后就视为适配完成。首次验收同时检查文字截断、命中框、弹窗遮罩、UI 点击穿透地图、键鼠焦点与关闭返回。

## 当前 IMGUI 的短期做法与后续迁移

**本轮实现优先**：保留已有玩法和 IMGUI，集中调整皮肤/间距/布局，统一面板、主次按钮、资源徽章和武将卡框，加入可替换的原创/获准肖像。先将三个典型界面做一致，再评估控件迁移。研究用的官方图片不能直接当正式 UI 皮肤。

**中期候选**：uGUI 适合当前 GameObject 与 MonoBehaviour 工程习惯，Canvas + 预制体卡牌可让美术直接迭代。UI Toolkit 也可行，尤其适合大量列表与全局样式；选型应做一屏武将列表原型，比较中文字体、滚动、卡牌动画、输入和维护成本。不要同时重做全部页面、换渲染管线和换 UI 框架。

## 对比验收

- 地图居于视觉中心，非必要静态栏可收起；选地状态和行军路径先于装饰可见。
- 玩家两秒内可以找到武将姓名、星级、等级、是否上阵；空阵容槽位不依赖长段说明。
- 主按钮在灰度截图里仍可识别；不能只靠红/绿色区分敌我或可用状态。
- 对同一存档与相机位置保存改前/改后截图；记录实际分辨率、UI缩放、选中对象，再比较。
