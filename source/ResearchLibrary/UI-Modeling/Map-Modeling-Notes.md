# 地图与模块化建模技术笔记

目标 Unity 6000.3.27f1，保持现有内置渲染管线。2026-10-24 已检查 `Packages/manifest.json` 无 URP/HDRP，`GraphicsSettings.asset` 的 `m_CustomRenderPipeline` 为空。现有逻辑地图与俯视相机可以保留，首先替换视觉表达。

## 先把“地块”与“地形”分开

逻辑层保留坐标、资源、等级、归属、行军成本；显示层由连续底地、河流/道路、山体/树林、城市/营寨、选中边界与标记组成。一个资源地可以在连续地表上放农田、矿坑或草堆，不需要整个格子换成一种高饱和颜色。选中、敌我占领、可达范围用独立描边或半透明覆盖显示，缩放时可减弱/隐藏常驻网格。

最短实现路线是将现有平面视觉整合为分块网格或连续地表，添加少量共享材质的模块。只有需要编辑器雕刻、大范围高度变化和成熟地形绘制时才引入 Unity Terrain；不把迁移 Terrain 当作首轮美化的必需步骤。

## 官方机制依据

- [Unity 6000.3 Terrain Layers](https://docs.unity3d.com/6000.3/Documentation/Manual/class-TerrainLayer.html)：Terrain Layer 可跨地形块复用，底层纹理覆盖地表，其余层可绘制叠加。层数影响渲染；内置管线每次纹理 pass 处理四层，继续增加会追加 pass。URP/HDRP 专用遮罩或密度混合选项不能直接当作当前内置材质功能。
- [Unity 6000.3 邻接地形](https://docs.unity3d.com/6000.3/Documentation/Manual/terrain-CreateNeighborTerrains.html)：邻接工具可匹配边界高度；相同 Grouping ID 和 Auto Connect 参与连接。手工或程序生成地表仍需检查边界顶点、法线和纹理坐标一致，不能仅靠位置靠近就认为接缝消失。
- [Unity 6000.3 LOD Group](https://docs.unity3d.com/6000.3/Documentation/Manual/class-LODGroup.html)：LOD 阈值按对象屏幕高度占比定义，可重新计算包围范围。以真实游戏相机预览每档效果，比按美术软件视窗的距离判断可靠。
- [Blender 4.5 LTS Decimate](https://docs.blender.org/manual/en/4.5/modeling/modifiers/generate/decimate.html)：可用 Collapse 减面，Planar 处理平坦区域，支持边界限制；比例与三角形计数有关。自动减面只能作为起点，必须复查城门、屋脊、帐篷轮廓和 UV。

## 区域资产设计建议

以下是游戏艺术与工程提案，具体东汉/鲜卑/东北历史形制应由艺术研究和史料复核。

| 层级 | 汉地 | 草原 | 东北 |
|---|---|---|---|
| 大色块 | 低饱和绿褐、农田条带、河谷 | 草黄绿大面积过渡、裸地、稀疏岩石 | 深绿林地、冷褐泥土、水网 |
| 聚落轮廓 | 夯土城墙、城门、密集低屋顶 | 圆顶/圆形营帐、围栏、畜群提示 | 木栅围合、木屋、少量汉式城建混合 |
| 资源识别 | 成组田畦、石坑、铁矿设施 | 干草垛、牧群、石矿 | 林缘采集点、渔猎设施、矿点 |
| 地形剪影 | 缓丘与山脉串联，山脚自然扩展 | 开阔起伏，少量岩丘 | 树冠簇、丘陵、河岸断续过渡 |

**河流**：沿中心线生成带状水面，宽度缓变；两侧有泥滩/浅色岸边、零散石块和植被，让河岸进入地表。急转弯检查自交，河面和岸面留足高度差避免闪烁。首轮采用简单不透明或低成本材质，水面细节不应盖过行军路径。桥梁、渡口与河流是否阻行属于玩法规则，不能靠美术形状偷偷改变。

**山体**：3–5 个基础山块旋转、缩放组合成山脊；共享岩石/植被材质，保留迎光/背光轮廓。禁止每格同高、同朝向的金字塔。近景加山脚与岩块过渡；远景保留山脉大形即可。

**植被**：先做 3 种树冠剪影和 2–3 个林簇，改变角度与尺度。森林占地有疏密与林缘，避免树整齐排成网格。首轮用不透明几何树冠可减少大面积透明叶片叠层，艺术风格允许时再增加少量叶卡。

**城池套件**：直墙、转角、城门、望楼、屋顶组、主楼、旗帜、底座共用一套比例；默认 AI 城按城门/城墙层次和旗帜区分等级，不能只用放大倍数。部落营地用帐篷、木栅、火塘、旗杆、货堆模块，留出中心空地。商贸角色可用市场/货车图形识别，避免与军城完全同形。

## 相机尺度决定细节预算

先固定常用近/中/远三档正交缩放，保存同一城市和林簇截图。用实际投影像素量测模型尺寸：当屋顶只占约十几像素时，柱子和门钉不会改善辨识，应把预算用于屋顶轮廓和明暗。

初始试验预算（非硬性引擎限制）：城市模块组合 LOD0 约 2k–6k 三角形，营地 1k–3k，树簇 300–1.2k；LOD1 尝试保留约 40%–60% 几何，LOD2 只留主要剪影。资源物不设复杂碰撞，拾取沿用逻辑格或简化碰撞体。真实预算必须在目标设备、实际可见城市数和 UI 打开时测量，达标后再加细节。

地表分块可从 16×16 或 32×32 **逻辑格/块**试验；这不是 Unity Terrain heightmap 分辨率。块大小要根据可见对象数、重建时间和边缘接缝选择。不要为了小型原型立刻引入世界流式加载和大型资产管理架构。
